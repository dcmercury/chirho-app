# August 18, 2026 — Current State and Next Tasks

## Current architecture

- `chirho-app` is the Expo/React Native client.
- `dailyoffice` is the shared Next.js API and administration backend.
- Mobile community data comes from DailyOffice APIs.
- Current communities are stored in MongoDB collection `chirho_communities`.
- The mobile app does not use the legacy `chirho_churches` collection.
- User identity and authorization use Clerk IDs and metadata.
- Local development currently uses `http://127.0.0.1:3020` and Clerk development keys.

## Confirmed working

- DailyOffice community administration creates records in `chirho_communities`.
- Mobile community search reads those same records.
- Mobile home loads the active community's name, tradition, branding, logo, and background.
- Profile drawer community joining:
  - Adds the community to Clerk `publicMetadata.communityIds`.
  - Sets `chirho_userSettings.communityuuid` as the active community.
- Group administration is tied to the group's Clerk admin ID and is separate from community administration.
- Loved-one prayer text is saved before audio generation starts.
- ElevenLabs audio is generated asynchronously and attached to the same prayer UUID.
- Display text is stored separately from the tagged ElevenLabs text.
- Local date, time of day, timezone, tradition, categories, and virtues are passed into loved-one prayer generation.

## Known gaps

### Community membership

- Onboarding calls `/api/mobile/communities/join`, but that route only updates Clerk metadata.
- Onboarding does not currently set `chirho_userSettings.communityuuid`.
- Profile drawer joining does both operations, creating inconsistent behavior.
- Leaving a community should remove membership metadata and safely select or clear the active community.

### Community administrators

- DailyOffice admin authorization checks Clerk:
  - `publicMetadata.role`
  - `publicMetadata.communityIds`
- The MongoDB `community.adminUsers` list alone does not grant access.
- Adding or removing an administrator is not one atomic operation across Clerk and MongoDB.
- The native app does not currently expose community-admin capabilities or controls.
- Community administration is separate from group administration.

### Environment alignment

- The current local app reports Clerk development keys.
- TestFlight/production must use:
  - The production Clerk publishable key.
  - The matching DailyOffice production Clerk secret key.
  - The production DailyOffice/Vercel API URL.
  - The same production MongoDB database used by DailyOffice admin.
- Verify EAS production variables instead of relying on local `.env` files.

### Data model

- `community-service.ts` is the active service.
- `church-service.ts` and `chirho_churches` are legacy paths that can cause divergent data.
- Existing church records may require migration or explicit compatibility handling.
